# ADR 0013: Stable integration boundary

**Status:** Accepted

PR 13 establishes the engine's external machine-to-machine boundary without changing the earlier human/admin API into a prematurely hardened public API.

## Service principals and credentials

The existing `Principal.kind = service` identity is reused.

A service-account issuance operation creates:

- one service principal;
- one API credential;
- a random bearer token returned once.

Only the SHA-256 token hash and a short non-secret prefix are stored.

Credentials have explicit scopes and may expire or be revoked.

PR 16 will add fine-grained RBAC and harden the control-plane issuance/revocation endpoints. PR 13 protects the new execution endpoints with service credentials now.

## Idempotency

Mutating integration operations that can be safely replayed require `Idempotency-Key`.

Keys are scoped to a credential, not globally.

The record binds:

- credential;
- key;
- HTTP method;
- logical route;
- canonical request hash;
- response status/body/content type.

An identical completed request replays the stored result. Reusing the same key for a different request returns a conflict.

## Cursor pagination

Resource and event feeds use opaque cursors derived from `created_at + id`.

The cursor is stable across ordinary inserts and does not expose page numbers as synchronization state.

## Durable event outbox

Every tamper-evident audit-event insertion triggers creation of one `integration_events` outbox row.

Active webhook subscriptions matching the event type receive one delivery record.

The compliance transaction commits independently of network delivery. The worker later consumes delivery records using `FOR UPDATE SKIP LOCKED`.

This prevents a remote webhook outage from rolling back a compliance decision.

## Webhook secrets

Raw webhook signing secrets are not stored.

The secret is derived from:

```
HMAC-SHA256(server master secret, subscription ID)
```

The derived secret is returned when the subscription is created and can be regenerated by the server.

Delivery signatures are:

```
sha256=HMAC(secret, "<timestamp>.<raw JSON body>")
```

Headers include the event ID, timestamp, and signature.

Webhook URLs require HTTPS and cannot contain URL credentials. Network-level egress/SSRF hardening remains part of PR 16.

## Import/export

Resource imports use a durable mapping key:

```
organization + source + entity type + external ID
```

Repeated imports update the mapped resource rather than creating a second one.

Exports use a portable versioned JSON bundle.

## Cross-engine adapters

The master engine exposes neutral adapter contracts rather than importing Registry or Case engine code.

Registry projection contains:

- resource identity/status;
- latest compliance check;
- currently valid certifications;
- unresolved finding counts.

Case trigger feed contains:

- disputed findings;
- unresolved high/critical findings requiring human review;
- overdue remediation.

These are transport-neutral interfaces implemented by the integration service and exposed through authenticated HTTP routes.

## OpenAPI

`/openapi.json` exposes an OpenAPI 3.1 route-complete document covering every API route in the engine.

Earlier routes retain generic object schemas until their DTOs are explicitly versioned. PR 13 fully declares the new service-bearer security scheme and idempotency headers.
